# 智能问答五版对比（白话版）

> 对应代码目录：`ZNWD`、`ZNWD1`、`ZNWD2`、`ZNWD3`、`ZNWD4`  
> 面向：想快速知道「这几套代码到底差在哪」，不想先啃架构文档的人。

---

## 先记住一句话

**五套都在答同一类问题**（装备、试验项目、考核指标、试验方法、标准条文等），都要查 **图数据库（Neo4j）**，有的还要查 **文档库（Chroma）**。

**真正的区别只有一件事：**

> **「该查什么、怎么查」这件事，主要是大模型说了算，还是程序说了算？**

---

## 用吃饭来比喻（5 秒看懂）

| 版本 | 比喻 |
|------|------|
| **ZNWD（现网默认）** | 服务员先按**常见套餐**快速上菜；上不齐再叫**大厨自己进厨房挑食材做多轮菜**（大模型自己反复查库）。 |
| **ZNWD1** | **前台经理**先填一张「业务单」（查项目还是查指标…），厨房按**固定菜谱**做菜；单子填不准就走**通用做法**。最后**专门有个文案**把菜名写成人话（合成大模型）。 |
| **ZNWD2** | 客人说一句，**翻译员**写成「我要从 A 查到 B」；**地图软件**算最短路线；**服务员**按清单念结果——**没有文案润色**。 |
| **ZNWD3** | **程序先猜**你要什么、去库里核对实体；大模型只干**一件小事**（提实体或二选一），其余全是程序。 |
| **ZNWD4** | 和 ZNWD1 **同一套厨房**；换的是**前台分两趟填单**（先选大类，再在缩小后的菜单里选具体项），程序最后**强制对一下图谱里有没有这个东西**。 |

## 各版「从提问到出字」怎么走（白话步骤）

### ZNWD（现网，默认最新流水线）

1. 读聊天记录，把短追问补全（例如上一句说了坦克，这句只说「那指标呢」）。
2. **程序先看**：是不是闲聊？要不要查库？
3. 若要查库：**先用规则和关键词**猜意图（列举、查关系、查标准章节…），并在图里找「焦点词」对应哪个节点。
4. 猜得不踏实 → **再问大模型**补一刀路由。
5. 命中「快路径」→ 按**固定查库步骤**查 Neo4j / Chroma；数据够整齐 → **直接表格/列表给用户**，结束。
6. 快路径不够 → 启动 **Agent**：大模型自己决定再查几次图、几次文档，最后流式写答案。

**和其它的最大不同：** 唯一一套默认带 **「大模型自己反复查库」** 的兜底；其它版本基本都把查库步骤锁死在程序里。

**包内还有老版本 v1～v5**（双路检索、先规划再查等），前端默认不走那些接口，除非专门开环境变量。

---

### ZNWD1（独立新包，四层业务）

1. 打招呼 → 直接闲聊，不查库。
2. **路由大模型**看一张「8 类业务 + 场景」表（例如：装备查项目、项目查方法、标准查章节…），填关键词槽位；需要时调用工具：去图里探测词、读最近几轮聊天。
3. **程序核对、纠正**路由单（防止把「标准」和「方法」搞混等）。
4. 业务单置信度高 → 走 **预制菜谱（Playbook）**（几步查库写死在程序里，包括「先要项目再要方法」这种组合题）。
5. 置信度低 → 走 **7 种通用查法**（按名称找节点、查一跳关系、查文档等），仍由程序展开具体步骤。
6. 查完：能原样列出就 **直出**；要归纳的 → **第二个大模型**专门写人话答案。

**核心思想：** 大模型只负责「填业务单」，**不负责**设计 SQL/Cypher、不负责决定底层查库指令编号。

---

### ZNWD2（图规划，最「硬」）

1. **大模型只做一件事**：把问题变成结构化意图（例如：从「装备」查到「指标」，装备名=无人机，环境=高原）。
2. **程序**先看有没有现成「快捷套餐」（宏）：查指标、查项目、查方法带环境等。
3. 没有套餐 → 在**图谱关系图**上算一条最省事的路线（带权重，避免「查指标」误绕到「试验项目」）。
4. 按路线用几种固定动作查 Neo4j（定位节点、沿边扩展、过滤属性…）。
5. **程序把行数据排成 Markdown 列表**给用户——**没有第二个大模型润色**。

**适合：** 要路径可解释、要省模型钱、能接受答案像「查询结果清单」而不是小作文。

**和 ZNWD1 的关系：** 意图 ≈ ZNWD1 的路由结果；快捷套餐 ≈ ZNWD1 的菜谱；算路 ≈ ZNWD1 的通用路径白名单。

---

### ZNWD3（程序主导，大模型「打下手」）

在 **ZNWD1 的查库和写答案厨房** 上，换掉「前台填单」方式：

**共同前置（不靠大模型）：**

- 用规则从句子里抠槽位（有没有装备名、环境名、项目名…）。
- **直接去图数据库探测**这些词是否存在、是什么类型节点。

**然后二选一（环境变量切换）：**

| 模式 | 大模型干什么 | 程序干什么 |
|------|--------------|------------|
| **提取模式（默认）** | 一次短对话：列出实体 + 粗意图 | 对照探测结果，**拼出**和 ZNWD1 一样的业务单 |
| **确认模式** | 程序先列出 2～3 个可能业务，大模型**只选一个** | 规则表生成候选 |

之后：**核对业务单 → 菜谱或通用查法 → 查库 → 直出或合成**，和 ZNWD1 一样。

**独有兜底：** 业务对不上时，程序在预设的「一跳 / 两跳」路径表里自动找怎么查。

**和 ZNWD1 比：** 更快、提示词短、**不让**路由大模型多轮用工具；代价是复杂问法更依赖规则和探测质量。

---

### ZNWD4（ZNWD1 的厨房 + 新前台）

**查库、直出、合成答案** 与 ZNWD1 **同一套逻辑**（可以看成 ZNWD1 的演进前台）。

**前台变化（白话）：**

1. 先补全短追问（同 ZNWD1）。
2. 有些句式 **程序直接锁定** 业务（弱模型时甚至**跳过**前两步大模型）。
3. 否则 **第一次问大模型**：这道题的大目的（查装备类？查方法？闲聊？）+ 关键词。
4. **程序**根据目的，只拿出**相关的一小份路线菜单**给模型看（不是整张 8 类大表一起塞）。
5. **第二次问大模型**：在缩小菜单里选一条 **路线编号** + 填槽位。
6. **程序第三步（强制）**：再去图里探测、校验、对齐，转成 ZNWD1 能识别的业务单。
7. 后面完全走 ZNWD1：核对 → 菜谱 → 查库 → 直出/合成。

**和 ZNWD1 最直白的区别：**

| | ZNWD1 | ZNWD4 |
|--|-------|-------|
| 路由问法 | 一次让模型填完整张业务单 | **分两次**，第二次只看缩小菜单 |
| 对外说法 | 「业务类 + 场景」 | 统一叫 **「路线编号」**（内部仍映射到业务和场景） |
| 实体类型谁信 | 模型 + 工具探测 + 程序纠偏 | **更信程序探测**，模型不最终决定节点类型 |
| 纠错力度 | 程序纠偏较多 | 高置信路线时 **少做一部分** 程序纠偏（为速度） |

## 最容易混的 3 个点（直白澄清）

### 1. ZNWD 和 ZNWD1 不是「新旧替换关系」

- **ZNWD**：现网前端默认连的包，里面叠了 v1～v6 多年演进，**默认 v6**。
- **ZNWD1**：**另起炉灶**的独立包，业务表、路由单格式、模块划分都重新设计，**不引用** ZNWD 代码。

### 2. ZNWD3 / ZNWD4 不是全新查库方式

- **ZNWD3**：换的是「谁填业务单」，**查库和写答案仍用 ZNWD1 那套**。
- **ZNWD4**：换的是「怎么填业务单」，**查库和写答案仍用 ZNWD1 那套**。

### 3. ZNWD2 是另一条路线

- 不玩「8 类业务 + 菜谱」，而是 **「意图类型 + 图最短路径 + 清单式答案」**。
- **一般不经过「第二个大模型写小作文」**。

## 按你的需求选哪套？

| 你想要… | 建议先看 |
|---------|----------|
| 和当前页面一致、要快、还要能处理很花的问法 | **ZNWD** |
| 业务清晰、能验收「这道题必须走查项目」、答案要润色 | **ZNWD1** |
| 日志里要能看懂「从 A 查到 B 走了哪几步」、答案列表即可 | **ZNWD2** |
| 延迟敏感、模型弱、愿让程序多干活 | **ZNWD3** |
| 路由老选错、用小模型（如 14B 量化），仍要 ZNWD1 的答案质量 | **ZNWD4** |

## 同一句题，五版「谁动脑子」对比（示例）

**用户问：** 「坦克在盐雾环境有哪些试验项目？」

| 版本 | 谁理解题意 | 谁定查法 | 谁查库 | 谁写给人看的答案 |
|------|------------|----------|--------|------------------|
| ZNWD | 规则 + 可能再问模型 | 模板步骤 或 Agent 自己定 | 程序 或 Agent | 直出 / 整合模型 / Agent |
| ZNWD1 | 路由大模型填「装备+环境→项目」 | 程序菜谱 | 程序 | 直出 或 合成大模型 |
| ZNWD2 | 意图大模型写「查项目+有环境」 | 程序快捷套餐「查项目_有环境」 | 程序 | **程序列表** |
| ZNWD3 | 程序槽位 + 探测；模型只提取实体 | 程序拼业务单 + 菜谱 | 程序 | 直出 或 合成大模型 |
| ZNWD4 | 模型先选「查项目」再在菜单选「装备+环境」；程序对齐「坦克」「盐雾」 | 程序菜谱 | 程序 | 直出 或 合成大模型 |
