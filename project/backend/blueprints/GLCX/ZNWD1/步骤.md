根据代码和架构文档，智能问答后端从用户输入到返回的完整流程如下（以"无人机有哪些项目"为例）：

## 端到端处理步骤

### 1. HTTP 入口接收 (`__init__.py:82`)
- 前端 POST `/api/znwd1/chat/stream`，携带 `{question: "无人机有哪些项目", sessionId, userId}`
- 初始化 SSE 流式响应，发送即时思考首包 `thinking_start` + "已收到您的问题，正在分析…"

### 2. 主流水线启动 (`pipeline.py:179`)
- `stream_znwd1_chat()` 被调用，传入 OpenAI client、model、Neo4j driver、Chroma collection

### 3. 路由大模型规划 (`znwd1_langchain_routing.py:110`)
**`stream_route_plan()` 执行：**
- 构建系统提示词：包含 8 类用户业务表、图谱本体（7 类节点+3 种关系）、消歧规则、7 种原子动作范式
- 绑定 3 个工具：`znwd1_probe_keyword`（关键词探测）、`znwd1_history_recent_qa`（历史续问）、`znwd1_history_similar_questions`
- 调用 LLM（最多 2 轮工具调用）

**对于"无人机有哪些项目"：**
- LLM 识别为 `user_biz=UBIZ_TEST_PROJECT`, `scenario=by_equipment`
- 提取槽位 `params_draft.equipment_keywords=["无人机"]`
- 可能调用 `znwd1_probe_keyword(keyword="无人机")` 在 Neo4j 中探测是否存在"无人机"节点，返回节点类型、Id、名称
- 输出 RoutePlan JSON：
  ```json
  {
    "user_biz": "UBIZ_TEST_PROJECT",
    "scenario": "by_equipment",
    "match_confidence": "high",
    "answer_strategy": "db_synthesize",
    "params_draft": {"equipment_keywords": ["无人机"]},
    "probe_snapshot": {"best": {"node_type": "Equipment", "id": "...", "name": "无人机"}}
  }
  ```

### 4. 计划对齐 (`plan_reconcile.py:439`)
**`reconcile_route_plan()` 执行：**
- 检查是否为打招呼 → 否
- **Playbook 优先**：`user_biz=UBIZ_TEST_PROJECT`, `scenario=by_equipment`, `match_confidence=high` → 进入 Playbook 展开
- 调用 `expand_playbook()` 查找对应场景规格

### 5. Playbook 展开 (`playbook_resolver.py:598`)
- 查找 `UBIZ_TEST_PROJECT/by_equipment` 的场景规格 → 参数构造器 `rel_eq_tp_fwd`
- 归一化槽位：`equipment_keywords=["无人机"]`, `focus="无人机"`
- 调用 `_pb_rel_eq_tp_fwd()` → 返回 `(BIZ_REL_ONE_HOP, params)`
  - `params = {from_type: "Equipment", to_type: "TestProject", rel_type: "CON", match_mode: "fuzzy", focus: "无人机"}`
- 返回 playbook 结构：`business_steps=[(BIZ_REL_ONE_HOP, params)]`, `multi_step=False`

### 6. 业务展开为元操作 (`business_expand.py`)
**`expand_business(BIZ_REL_ONE_HOP, params)` 执行：**
- 将 `BIZ_REL_ONE_HOP` + 参数映射为 L4 元操作步骤：
  ```python
  [
    {
      "op_code": "neo_relation_query",
      "params": {
        "from_type": "Equipment",
        "to_type": "TestProject",
        "rel_type": "CON",
        "where_side": "from",
        "match_mode": "fuzzy",
        "from_field": "Name",
        "focus": "无人机"
      }
    }
  ]
  ```

### 7. 执行元操作 (`executor.py`)
**`execute_meta_steps(neo4j_driver, chroma_collection, steps)` 执行：**
- 遍历步骤，根据 `op_code` 分发到对应引擎：
  - `neo_relation_query` → 调用 Neo4j Cypher：
    ```cypher
    MATCH (n:Equipment)-[:CON]->(m:TestProject)
    WHERE n.Name CONTAINS '无人机'
    RETURN m LIMIT 120
    ```
- 返回 `neo_rows`（试验项目列表）、`chroma_rows`（空）

### 8. 回答策略判定 (`pipeline.py:340`)
- `business_id=BIZ_REL_ONE_HOP` 在直出白名单中
- `use_direct=True` → 走 `format_direct_answer()`

### 9. 格式化直出 (`formatters.py`)
- 将 `neo_rows` 按业务模板格式化为文本：
  ```
  无人机相关的试验项目有：
  1. 项目A
  2. 项目B
  ...
  ```

### 10. SSE 推送 (`__init__.py:142`)
依次推送事件：
- `thinking_start` → "已收到您的问题，正在分析…"
- `thinking` → 路由里程碑："正在理解您的问题并规划检索方案…" → "方案就绪：试验项目"
- `step` → `{"type": "routing", "status": "done", "message": "方案就绪：试验项目"}`
- `step` → `{"type": "retrieval", "status": "loading", "message": "正在检索知识库…"}`
- `search_keywords` → 表格关键词
- `source_data` → Neo4j 结果 + Chroma 结果
- `step` → `{"type": "retrieval", "status": "done", "message": "检索完成 Neo4j=5 Chroma=0"}`
- `thinking` → "正在整理答复…"
- `answer` → `{"content": "无人机相关的试验项目有：..."}`
- `done` → `{"fullAnswer": "...", "fullThinking": "..."}`

### 11. 记忆存储 (`pipeline.py:80`)
- `_finalize_memory()` 将问答对写入 Redis（`znwd1:{userId}:{sessionId}`）

## 关键设计原则
1. **大模型不选 op_code/Cypher**：只输出业务 ID + 槽位，程序确定性映射到元操作
2. **Playbook 优先**：高置信命中预编排动作序列，低置信降级 L3 原子动作 fallback
3. **清单库优先**：领域问题禁止 `direct_llm`，必须查 Neo4j/Chroma
4. **多步一次合成**：拼装业务（如"项目+方法"）多步查库后合并证据，仅调用一次合成大模型
