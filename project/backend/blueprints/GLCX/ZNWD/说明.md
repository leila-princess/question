## 三、核心功能模块

### 1. SSE 流式对话 (`__init__.py` → `chat_stream_v4`)

**路由**: `POST /api/znwd/chat/stream_v4`

**请求参数**:
```json
{
  "question": "用户问题",
  "sessionId": "会话ID",
  "userId": "用户ID"
}
```

**处理流程**:
```
1. 接收请求参数
2. 从 Redis 加载历史记忆和摘要
3. 组装消息列表：[system_prompt, summary?, history..., user_question]
4. 估算 token 数，超限时直接返回 token_limit 事件
5. 调用 llm_stream_single() 获取生成器
6. 逐事件 yield 为 SSE 格式返回前端
7. 对话结束时保存记忆到 Redis，必要时自动保存到 MySQL
```

**SSE 响应格式**:
```
event: thinking_start
data: {}

event: thinking
data: {"content": "思考内容片段"}

event: answer
data: {"content": "回答内容片段"}

event: done
data: {"fullAnswer": "完整回答"}
```

**关键设计**:
- 使用 `Response(stream_with_context(generate()), mimetype='text/event-stream')` 实现流式
- `stream_with_context` 确保生成器内能访问 Flask 上下文
- 超时/错误处理完善

### 2. Agent 工具调用与流式解析 (`services_v4.py`)

**核心函数**: `_stream_single_llm()`

**实现模式**（参照 `multi_agent_engine.py` 的流式处理）:

```
LLM Stream (chunk by chunk)
    ↓
Buffer Accumulation
    ↓
Tag Parsing ([THINK]/[CONTENT])
    ↓
Immediate Event Yield
    ↓
SSE Response to Frontend
```

**流式处理细节**:

| 步骤 | 说明 |
|------|------|
| `buffer += delta.content` | 累积 LLM 返回的每个 chunk |
| 检测 `[THINK]` | 进入思考模式，yield `thinking_start` |
| 检测 `[/THINK]` | 结束思考，yield 完整思考内容 |
| 检测 `[CONTENT]` | 进入回答模式 |
| 检测 `[/CONTENT]` | 结束回答，yield 完整回答内容 |
| `TAG_TAIL=12` | 每次保留 12 个字符在 buffer 中，防止标签被截断 |
| 中间 chunk | 每收到新 chunk 就 yield 出去，实现真正的流式 |

**工具调用机制**:

| 工具 | 参数 | 返回值 |
|------|------|--------|
| `query_neo4j` | `cypher: string` | Neo4j 节点列表（labels + properties） |
| `search_knowledge_base` | `query: string` | 知识库匹配片段列表 |

**工具调用流程**:
1. LLM 返回 `tool_calls` 字段
2. 解析工具名和参数
3. 执行对应工具函数
4. 将结果以 `tool` role 返回给 LLM
5. 递归调用 `_stream_single_llm` 继续流式生成

### 3. Redis 短期记忆 (`memory_store.py`)

**类**: `RedisMemoryStore`

**Key 格式**:
- `memory:{user_id}:{session_id}` → 摘要和最近一轮对话
- `messages:{user_id}:{session_id}` → 完整消息列表（Redis List）

**TTL**: 默认 1800 秒（30分钟）

**核心方法**:

| 方法 | 功能 |
|------|------|
| `get(user_id, session_id)` | 获取记忆数据 |
| `get_summary(user_id, session_id)` | 获取摘要 |
| `get_messages(user_id, session_id)` | 获取完整消息列表 |
| `add_message(user_id, session_id, role, content)` | 添加消息到列表 |
| `clear_messages(user_id, session_id)` | 清空消息 |
| `set_summary(user_id, session_id, summary)` | 设置摘要 |
| `delete(user_id, session_id)` | 删除记忆（含消息） |

### 4. MySQL 持久化 (`models.py`)

**表**: `chat_history`

**字段**:

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INT AUTO_INCREMENT | 主键 |
| `session_id` | VARCHAR(50) | 会话唯一标识 |
| `title` | TEXT | 对话标题（截断后30字） |
| `messages` | JSON | 完整消息列表 |
| `message_count` | INT | 消息数量 |
| `user_id` | VARCHAR(50) | 用户ID |
| `user_name` | VARCHAR(100) | 用户名 |
| `created_at` | TIMESTAMP | 创建时间 |
| `updated_at` | TIMESTAMP | 更新时间 |

**核心函数**:

| 函数 | 功能 |
|------|------|
| `save_conversation()` | 保存对话（前端手动保存调用） |
| `get_history_list()` | 获取历史列表（分页） |
| `get_history_detail()` | 获取单条历史详情 |
| `get_history_by_session()` | 按 sessionId 获取 |
| `delete_history()` | 删除单条 |
| `clear_all_history()` | 清空全部 |
| `save_conversation_mysql()` | 后端自动保存（摘要生成后调用） |

### 5. Prompt 设计 (`prompts_v4.py`)

**`SYSTEM_PROMPT_SINGLE`** — 单轮 Agent 系统 Prompt

包含:
- 可用数据结构说明（Neo4j 节点类型、关系）
- 可用工具定义（`query_neo4j`、`search_knowledge_base`）
- 工作流程（分析问题 → 调用工具 → 整合数据 → 生成回答）
- 重要规则（禁止编造、节点类型转中文、安全红线）
- 输出格式要求（`[THINK]...[/THINK]` + `[CONTENT]...[/CONTENT]`）

**`SUMMARY_MERGE_PROMPT`** — 摘要合并 Prompt

用于将新对话合并到已有摘要中，保持 100-200 字精炼。

## 五、SSE 事件类型

| 事件类型 | 数据 | 触发时机 | 前端动作 |
|----------|------|----------|----------|
| `thinking_start` | `{}` | 检测到 `[THINK]` 标签 | 初始化思考面板 |
| `thinking` | `{"content": "..."}` | 思考过程中每个 chunk | 追加到思考过程 |
| `tool_call` | `{"name": "...", "args": {...}}` | LLM 调用工具时 | 显示工具调用信息 |
| `tool_result` | `{"name": "...", "result": [...]}` | 工具返回结果时 | 显示工具返回结果 |
| `answer` | `{"content": "..."}` | 回答内容每个 chunk | 追加到回答 |
| `done` | `{"fullAnswer": "..."}` | 对话完成 | 标记完成，保存记忆 |
| `error` | `{"message": "..."}` | 错误发生 | 显示错误信息 |
| `token_limit` | `{"message": "...", "estimatedTokens": N, "maxTokens": N}` | Token 超限时 | 提示用户开启新对话 |

## 八、关键实现注意事项

1. **流式传输**: 使用 `stream_with_context()` 包装生成器，保持 Flask 应用上下文
2. **JSON 序列化**: 使用 `default=str` 处理 Neo4j DateTime 对象
3. **Token 估算**: 使用 `tiktoken` 库估算 GPT-3.5-turbo token 数
4. **安全红线**: Cypher 查询禁止包含 `CREATE/DELETE/SET/MERGE` 等写入操作
5. **记忆管理**: Redis 存储短期记忆（30分钟 TTL），MySQL 持久化长期历史
